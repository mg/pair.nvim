# Security and privacy

Pair does not give an agent a Neovim file-writing tool. It applies completed source proposals to the unsaved buffer for the user to review. Direct API backends receive only bounded file and git inspection tools. Codex and ACP backends rely on their CLI sandbox or tool restrictions. A system prompt or an ACP permission prompt alone is not treated as a write boundary.

Antigravity runs inside a Pair-supplied filesystem sandbox (macOS Seatbelt or Linux bubblewrap), inherited by shell children. The filesystem is read-only except private agent state, the CLI login directory needed for credential refresh, private temporary storage, and explicitly configured `commands.writable_paths` inside the project. Output grants permit creation, replacement, and deletion without proposal review. Do not grant folders containing ordinary source. Pair validates existing output directories at launch; concurrent changes to permissions, hard links, or mounts by processes outside the sandbox are outside this boundary. Commands that ask external services or daemons to write files are not covered by filesystem restrictions on the local process. This sandbox does not restrict reads or network traffic. Unsupported hosts fail closed rather than running unrestricted.

Antigravity's isolated settings permit command execution while denying file-writing, MCP, and browser tools. Its native “unsandboxed” command grant means outside its own terminal sandbox; the process remains inside Pair's filesystem sandbox. Pair also stops on unsupported tool events, but that event check is detection, not preventive isolation. Shell commands inspect and test saved files on disk, not unsaved Neovim buffers.

The selected provider receives your prompt and attached editor snapshot, including unsaved changes by default. CLI tools may read additional files according to their own permissions. In particular, Codex read-only mode can read outside the workspace. Do not send sensitive project content to a provider you do not trust. Review or detach the full-buffer attachment before sending when needed.

Pair saves transcripts, agent session pointers, models, and direct API conversation history under Neovim's `stdpath('state')/pair`. New files are created with owner-only permissions. Pair masks common key patterns in saved chat text, but cannot identify every secret. The selected CLI may maintain its own separate history. `:PairNew` keeps prior Pair records; removing the Pair state directory removes those local records.

To report a vulnerability, use GitHub's private **Report a vulnerability** flow when available, or contact the maintainer privately through their GitHub profile. Include the affected version, backend, reproduction steps, and the concrete boundary crossed. Do not include credentials or private source content. Public bug reports are suitable for ordinary UI and compatibility problems.
